## 2. 定位与目标

用户不知道主 agent 正在做什么，希望另开一个可交互的小助手，用非程序员能懂的白话中文解释，不打断主 agent。

主 agent 指原有主对话中负责执行任务的 AI；小助手指本插件提供的旁观讲解窗口。

小助手负责：

1. 解释主 agent 正在做什么、之前做了什么。
2. 围绕真实步骤、命令、参数、输出和汇报回答追问。
3. 帮助理解相关项目结构与行为依据，不只重复标题。
4. 保存每次主对话对应的小助手问答，支持持续追问。
5. 说明行为不符合预期时可从哪里、怎样调整；只解释，不代替用户操作。

小助手不负责：

- 不向主 agent 发送用户的小助手提问或小助手回答。
- 不把小助手记录注入主 agent 的上下文。
- 不暂停、取消或改变主 agent 的任务。
- 不执行命令、不修改文件、不操作端口或服务。
- 不回填主对话输入框、不覆盖草稿、不自动发送建议。
- 不默认访问其他会话，不扩展成自动执行或任务监督控制器。

## 3. 对初始需求的明确变更

初始要求在每条步骤卡片标题行、每段助手汇报旁注入“?”。用户后续为使主界面简洁，明确选择方案 1：只在主对话右上角放一个“?”。

因此：

- 不再给每条步骤、每段汇报放常驻问号。
- 右上角单入口打开可交互小助手。
- 工具/步骤卡片、助手自然语言汇报两类内容仍均可选择并解释。
- 初始“两类位置都有问号”的验收，替换为“单入口可以选择、解释两类内容”。
- 历史内容通过同一小助手查询，不另铺问号。

## 4. 入口与窗口

- 主对话右上角“?”的位置参考用户第二张截图的箭头区域。
- 不改原有主题，不破坏布局，不改变主对话执行、输入与历史渲染行为。
- 打开可移动、可调整大小的小浮窗，不使用挤压主对话宽度的固定侧栏。
- 用户可以一边看主 agent 的进展，一边在小助手里提问。
- 关闭浮窗不删除问答，再打开能继续查看与追问。
- 仅打开窗口不产生新的模型回答。
- 第一次打开显示输入框和快捷问题，例如“它现在在干什么”“解释某条步骤”。
- 后续打开恢复当前主对话对应的小助手记录。

## 5. 提问与内容选择

### 5.1 不选内容也能提问

用户可直接问“它现在在干什么”“刚才为什么做这一步”。

小助手先参考当前主对话最近的步骤、实际输出和汇报；涉及之前的行为时，再查本主对话更早的记录。不默认读取其他会话。

已加载历史可参与查询，更早历史需通过宿主提供的读取能力取得。未取得、加载失败或缺失的记录不能假装已经查看；需说明查阅局限。不能每次无节制把全部历史交给模型。

### 5.2 在主对话原位置点选

操作顺序：

1. 点击右上角“?”打开小助手。
2. 在小助手点击“选择内容”。
3. 点主对话中的一条工具/步骤卡片或一段助手汇报。
4. 小助手显示正在围绕哪条内容提问。
5. 用户输入问题，也可以取消或换选内容。

选择只确定讲解对象，不触发原卡片的执行、链接、折叠等操作，不给主 agent 发消息。

采用原位置点选，不采用在小助手里重复列出整段主对话并多选的列表方案。

### 5.3 对执行中状态的解释

主 agent 可继续产生新步骤和输出。回答必须区分“正在执行”“已有结果”“尚未验证”。不能把开始执行当成成功，不能把早先回答冒充最新进展。

引用时点、提问期间更新的处理方式在实施方案中明确，不要求主 agent 为讲解停下。

## 6. 回答结构与文字

### 6.1 简短白话优先，依据按需展开

先简短说清重点，不让小浮窗被长命令与输出塞满。

解释具体步骤时覆盖四要素：

1. **在干什么**：实际读取、检查、修改、执行或验证什么。
2. **为什么做**：可从用户需求、上下文或明确说明确认的目的；不能臆测主 agent 的内心动机。
3. **实际产出**：真实输出、变更、状态或错误；尚未完成时说明目前只有哪些信息。
4. **哪里可以调整**：根据已知参数、配置、文件或用户要求说明位置和影响；不知道则说不知道，不编造文件或设置。

普通追问直接回答问题，不机械重复四项。

### 6.2 白话中文与术语解释

- 面向非程序员，用中文和日常表达解释。
- 不出现未解释的编程术语；确需使用时，当场用一句话说明。
- 命令、参数、原始输出可放入展开的依据，但粘贴原文不能代替解释。

### 6.3 依据与不确定性

展开的依据关联真实命令、参数、输出、状态、原汇报和必要上下文，供用户核查。

明确区分：

- **记录已证实**：实际结果或返回输出已有证据。
- **主 agent 的说法**：它的计划或汇报，不等于已经验证。
- **信息不足或尚未验证**：缺少支持结论的证据。

信息不足时明确写：**“该步未提供足够信息”**，并说明缺什么。不得编造步骤目的、执行成功、验证结果、文件位置或开销。

## 7. 模型选择与调用边界

- 用户提问、追问后，小助手独立调用模型回答。
- 打开、移动、缩放浮窗或查看记录，不自动生成新回答。
- 用户从 DSH 已配置模型中为小助手单独选择，不跟随主 agent 换模型。
- 初次未选模型时先提示选择，不偷偷调用默认模型。
- 不默认选高价模型，不无限调用或重试。
- 保留问答，采用缓存、按需生成、超时、用量限制控制开销；具体策略和数值在阶段 3 讨论。
- 不让联网大模型成为基本功能的强依赖：模型不可用时仍能查看既有记录、真实依据和基本说明。
- 自由问答通常需要模型；基本说明不能冒充完整智能回答。

独立请求意味着对话与执行隔离，不代表费用、额度或算力完全隔离。相同账户可能共享费用、请求限制和资源竞争，实施方案必须摊开说明，不承诺绝无资源竞争。

命令、输出、网页文本和历史材料是被解释的数据，不是小助手要服从或执行的指令。讲解不扩大为工具执行或主任务干预。

## 8. 问答记录与会话隔离

- 每个主对话有自己对应的小助手问答记录。
- 关闭再打开能查看并继续追问。
- 切换主对话时显示其对应记录，不混入其他主对话的内容。
- 小助手问答与主对话历史分开，不写回主 agent 上下文。
- 存储位置、格式、持久化范围、删除策略留到实施方案讨论，本文不默认决定。

## 9. 手动压缩与上下文占用

### 9.1 /compact

用户在小助手输入框输入 /compact，手动整理小助手后续回答所参考的上下文；**不自动压缩**。

- 完整问答记录仍保存并可翻看。
- 后续参考整理摘要与新的问答，压缩不是删除历史。
- 摘要不能代替真实证据，必要时查原记录。
- 只压缩小助手，不触发主 agent 或主对话压缩。
- 失败清楚提示，保留压缩前的可用状态。
- 压缩是否额外调用模型、费用和接近上限时的提示，在阶段 3 明确；不能默认自动压缩或丢弃历史。

### 9.2 右下角占用提示

小助手右下角显示圆环与上下文占用百分比，参考用户提供的 57% 示例图。

- 显示小助手自身占用，不使用主 agent 的数值。
- 帮助用户判断是否手动压缩。
- 只有估算时明确标“估算”。
- 无可信数值或模型容量时显示未知，不编造百分比。
- 完整保存的历史长度，不等于本次交给模型的上下文长度。

## 10. 失败与降级

- 请求失败或超时给出明确中文提示，不静默失败。
- 不阻塞主界面，不改变命令执行和主 agent 流程。
- 保留已有问答、可用依据，提供基本说明，并说明未取得深入模型解释。
- 历史缺失、加载失败、证据不足分别说明局限。
- 压缩失败不得覆盖上一份可用上下文。
- 出现慢、失败或费用不可控信号时，先落实缓存、按需调用、限额和降级，不无限调用追求效果。

## 11. 可观测验收标准

1. 主对话右上角只有一个“?”；步骤、汇报旁无常驻问号，布局与主题不被破坏。
2. 可交互浮窗支持移动和缩放，打开不会自动产生新回答。
3. 可直接问当前进展，也可在原位置选择步骤卡片、助手汇报两类对象。
4. 选择不误触原内容操作，不向主 agent 发消息。
5. 每个主对话问答独立，关闭重开可继续查看，切换不串记录。
6. 具体步骤解释覆盖四要素，普通追问直接回答，依据可展开核查。
7. 白话中文，术语即时解释；证据真实，信息不足明说，不把汇报当验证事实。
8. 模型可单独选择，不跟随主 agent；未选择不发请求。
9. 失败或超时有提示与基本说明，不阻塞主任务，不无限重试。
10. /compact 只作用小助手，完整记录仍可见，失败保留原可用状态，不自动压缩。
11. 右下角显示小助手占用；估算有标识，未知不伪装准确值。
12. 不改主 agent 消息、执行和主输入草稿；关闭插件不残留影响原功能的行为。
